# Лабораторна робота №7 - Програмування Java

## Тема: Абстрактні класи та інтерфейси
## Варіант 14: Фінансова установа

---

### 1. Теоретична частина

#### 1.1. Різниця між звичайним та абстрактним класом
- Екземпляри звичайного (конкретного) класу можна створювати безпосередньо через `new`. Екземпляри абстрактного класу (`abstract class`) створити не можна — він слугує базовим каркасом для нащадків.
- Абстрактний клас може містити абстрактні методи (`abstract void method();`) без тіла, які всі конкретні підкласи зобов'язані реалізувати. Звичайний клас не може містити абстрактних методів.

#### 1.2. Різниця між абстрактним класом та інтерфейсом
- **Множинність:** Клас може успадкувати лише один абстрактний клас (`extends SingleClass`), але здатний імплементувати будь-яку кількість інтерфейсів (`implements InterfaceA, InterfaceB`).
- **Стан (поля):** Абстрактний клас має стан (може містити звичайні поля екземпляра з модифікаторами `private`, `protected`, конструктори). В інтерфейсі всі поля є неявними константами `public static final`, а конструкторів немає.
- **Призначення:** Абстрактний клас задає родинну спорідненість сутностей за принципом *"є чимось"* (`is-a`), тоді як інтерфейс визначає контракт поведінки за принципом *"здатний робити"* (`can-do`).

#### 1.3. Кратне (множинне) успадкування в Java
- Множинне успадкування класів (`class C extends A, B`) у Java заборонено для уникнення неоднозначностей (проблема ромба / diamond problem).
- Реалізується за допомогою **інтерфейсів**: клас може імплементувати кілька інтерфейсів одночасно. Починаючи з Java 8, інтерфейси можуть також мати `default`-методи з базовою реалізацією, що дозволяє комбінувати поведінку з кількох джерел.

### 2. Практична частина

Систему класів з ЛР6 розширено та переведено на контрактну архітектуру:

1. **Інтерфейси:**
   - `Auditable`: визначає контракт проведення аудиту (`conductAudit()`) та розрахунку податкових зобов'язань (`calculateTaxObligation()`).
   - `Insurable`: контракт страхування ризиків (`registerInsurancePolicy(...)`).

2. **Абстрактний базовий клас `FinancialInstitution`:**
   - Оголошений як `abstract class FinancialInstitution implements Auditable`.
   - Містить загальний стан (`name`, `licenseCode`, `baseCapital`), конструктори та спільний метод `showInfo()`.
   - Оголошує абстрактні методи:
     - `public abstract void describeActivity();`
     - `public abstract double calculateAnnualRiskReserve();`
   - Реалізує базову логіку інтерфейсу `Auditable.conductAudit()`.

3. **Класи-нащадки:**
   - `Bank`: розширює `FinancialInstitution`, агрегує масив `Account[]` та імплементує інтерфейс `Insurable` (**кратне успадкування контракту**). Реалізує специфічні розрахунки резервного фонду банку та страхування вкладів.
   - `InsuranceCompany`: новий клас-нащадок `FinancialInstitution`, що моделює страхову компанію з власним пулом ризиків, розрахунком резервів та податків.

4. **Демонстрація у `Main`:**
   - Поліморфізм через масив абстрактного типу `FinancialInstitution[]`.
   - Робота з об'єктами через інтерфейсний тип `Insurable[]`.
